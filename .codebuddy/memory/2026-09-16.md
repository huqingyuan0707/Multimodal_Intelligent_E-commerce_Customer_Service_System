## 守卫死循环修复：/login↔/chat 互踢致 6180 次 /auth/me 风暴（2026-09-16）

- 现象：DevTools 6180 个 `ERR_CONNECTION_REFUSED`（GET /api/v1/auth/me），全来自 `index.ts:155` 守卫。直接原因是后端 8000 没启动，但 6180 次是前端 bug。
- 根因（经典互踢环）：sessionStorage 有 token + 后端不可达 → `loadMe()` 网络错误（`http.ts` catch 抛 5000，**不走 handle401、token 保留**）→ 守卫踢去 /login → /login 分支只看 `hasToken()` 又踢回 /chat → loadMe 再失败 → 无限环，每圈一次 /auth/me。401 场景无此问题（handle401 清 token）。
- 修复（router/index.ts 一处）：/login 弹回条件 `hasToken()` → `hasToken() && userStore.user`（身份已确认才弹回）。后端不可达时落在 /login 停住，LoginView 会提示「网络异常，请检查后端是否启动」；后端恢复后刷新页面 loadMe 成功即自动恢复。
- ⚠️ 通用坑沉淀：路由守卫里「弹回 /login」与「/login 弹回主区」两个条件必须用同一事实源（身份确认态），否则任何「token 在但身份取不到」的场景（后端挂/网络断/token 伪造）都会成环。lint 0 / typecheck 0，未提交。后端入口 `backend/app/main.py`（uvicorn app.main:app --port 8000）。
