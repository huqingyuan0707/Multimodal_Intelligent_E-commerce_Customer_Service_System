## 重启前后端（第 3 次）——「父进程 vs 监听进程」坑

用户指令：「重启」。**关键教训：端口占用的 PID ≠ 你启动的 PID。**

- `Get-NetTCPConnection` 报的 `OwningProcess` 是**真正监听 socket 的子进程**（uvicorn 的 python.exe / vite 的 node.exe）。
- 而无 IDE 终端时用 `Start-Process` 拉起的 `pnpm.cmd` / shell 包装进程只是**父进程**。只 `Stop-Process` 父 PID，子进程会变成孤儿**继续占用端口**，表现为「杀完端口仍在监听，但 PID 变了」。
- **正确做法**：杀之前先 `Get-CimInstance Win32_Process -Filter "ProcessId=<pid>" | Select ProcessId,ParentProcessId,Name,CommandLine` 确认身份，然后按 `CommandLine` 里的 `uvicorn`/`vite.js` 特征挑出真身杀，或用 `taskkill /PID <pid> /T /F` 连树杀。

### 本次启动参数（已跑通，日志统一放 `$env:TEMP\reai\`）
```powershell
$log = "$env:TEMP\reai"; New-Item -ItemType Directory -Force -Path $log | Out-Null
# 后端
Start-Process -FilePath "...\backend\.venv\Scripts\python.exe" `
  -ArgumentList "-m","uvicorn","app.main:app","--host","127.0.0.1","--port","8000" `
  -WorkingDirectory "...\backend" -WindowStyle Hidden `
  -RedirectStandardOutput "$log\backend.out.log" -RedirectStandardError "$log\backend.err.log" -PassThru
# 前端（Note: $log 是本次为收拢日志新引入的，之前是写在各自工程目录）
Start-Process -FilePath "pnpm.cmd" -ArgumentList "dev" `
  -WorkingDirectory "...\frontend" -WindowStyle Hidden `
```

- 日志放 `$env:TEMP\reai\` 而非工程目录，**避免污染仓库**（`backend/*.out.log` 这类易被误提交）。

### 关键设计决策（勿回退）
- **登录失败不能进 `handle401`**：后端密码错误返回 `401 + 1002`，若走中央处理会 `window.location.href='/login'`，在登录页触发**整页刷新，`ElMessage` 提示一闪即没**。故 `api.login` 用 `authRedirect:false` 豁免，错误由页面提示。
- **`perms` 与 `roles` 同值**：项目里 `require_perm()` 直接查 roles，故同源返回，前端 `roles` 管菜单/路由、`perms` 管按钮，单一口径避免两套权限源。
- **登出接口存在的意义是「确认身份 + 留痕」**：JWT 无状态、服务端不落会话表，`POST /auth/logout` 不吊销 token。

### 关键决策（勿回退）
- **配置 fail-fast ≠ 运行时降级**：`ENV=prod` 配置错就起不来（不带演示密钥/种子账号上线）；「外部依赖不可用走降级绝不 500」那条只针对运行时依赖，两者不冲突。
- **`PASSWORD_HASH_ITERATIONS` 可配但需重刷**：`verify_password` 内部复用 `hash_password`，改迭代次数必然让存量 `pwd_hash` 全部失效，已在 config docstring + `.env.example` + 两份文档四处显式标注。

### 发现的遗留（未改，待用户决定）
1. **`get_current_user` / `require_perm` 仍 `raise HTTPException`** → 返回体是 `{"detail": ...}`，**不是统一信封 `{code,msg,data,trace_id}`**，与 API 规范 §1/§2 冲突（401/403 缺 `code`）。smoke 只验状态码故未暴露。属「响应信封统一」范围，建议并入任务2。
2. **`authenticate()` 只按 `username` 查、未带 `tenant`**：users 表唯一键是 `(tenant, username)`，若两个租户有同名用户，`scalar_one_or_none()` 抛 `MultipleResultsFound` → 500；且登录表单无租户字段，无法区分租户。需设计决策（登录传 tenant，或 username 全局唯一）。
