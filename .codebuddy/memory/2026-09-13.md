## 补齐「软约束 + 硬约束」双层保障

用户已确认：skill 只是软提示，不能保证 AI 严格遵守，因此补了一层机械拦截。

### 启动方式（已跑通）

## 重启前后端（第 2 次，修掉依赖缺失）

用户指令：「重启」。按 memory 记录的固定流程操作：

### 重启步骤（沉淀为可复用流程）
1. `Get-NetTCPConnection -LocalPort 8000,5173 -State Listen` 找 `OwningProcess`。
2. `Stop-Process -Id <pid1>,<pid2> -Force`，等 2s 确认端口释放。
3. 后端：`Start-Process .\.venv\Scripts\python.exe -ArgumentList '-m','uvicorn','app.main:app','--host','127.0.0.1','--port','8000' -WindowStyle Hidden -RedirectStandardOutput backend.out.log -RedirectStandardError backend.err.log`（**必须重定向日志**，否则 GUI 模式下拿不到报错）。
4. 前端：`Start-Process cmd.exe -ArgumentList '/c','pnpm dev > dev.out.log 2>&1' -WindowStyle Hidden`。

### 本次踩坑与修复
- 后端冷启失败：`ModuleNotFoundError: No module named 'jwt'`（栈顶 `app/core/security.py:15`）。**根因**：`requirements.txt` 已有 `PyJWT>=2.8`，但 venv 没重装过。
- 修复：`backend/.venv/Scripts/python.exe -m pip install -r requirements.txt` → `pip check` 报 `No broken requirements found`。重启后正常。
- 教训：**改 `requirements.txt` 后必须重跑 install**；`security.py` 一旦存在，缺 PyJWT 会导致**导入 `app.main` 阶段**就崩（和之前 `python-multipart` 同类故障）。

### 工具使用坑（PowerShell）
- `execute_command` 底层已是 PowerShell，**命令里不要用 `&`**（`AmpersandNotAllowed`），多命令用 `;`。
- 通过 `powershell -Command "..."` 时外层双引号会先展开 `$_`，导致 `$_.Exception...` 被吞成 `.Exception...`。**改用 `curl.exe -s -o NUL -w "%{http_code}" <url>`** 取状态码最稳。
