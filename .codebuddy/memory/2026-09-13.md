## 补齐「软约束 + 硬约束」双层保障

用户已确认：skill 只是软提示，不能保证 AI 严格遵守，因此补了一层机械拦截。

- 结论：可靠性与优先级 = `CI 拦截 > pre-commit hook > ESLint/TS 报错 > always-apply 规则 > Skill > 文档`。
- Skill 定位收窄为「机器查不出来的约定」：分层职责、响应信封、错误码分段、租户隔离口径、SSE 事件名、目录分层。

### 常驻规则（alwaysApply，不依赖语义触发）
- `.codebuddy/rules/backend-red-lines.mdc`：分层／信封／错误码号段／租户隔离／配置不硬编码／降级不 500／必跑命令。
- `.codebuddy/rules/frontend-red-lines.mdc`：箭头函数、API 层唯一入口、SSE 必带 Authorization、目录分层、token 样式、401 中央处理。
- `.codebuddy/rules/quality-gate.mdc`：commitlint 格式、改动后必跑命令表、软硬约束关系、「禁止用 eslint-disable/noqa 绕过门禁」。
- 规则文件格式（.mdc frontmatter）：`description` / `alwaysApply` / `enabled`。

### 硬约束配置
- 前端 `frontend/`：`package.json`（scripts + lint-staged + devDeps）、`eslint.config.js`（ESLint 9 扁平配置，`func-style: expression` + `no-explicit-any: warn` + `no-restricted-globals: fetch`）、`.prettierrc`（与 skill 完全一致）、`.stylelintrc.json`（`color-no-hex` 拦硬编码主色）、`commitlint.config.cjs`、`.husky/{pre-commit,commit-msg}`、`.nvmrc`(20.11.0)、`.prettierignore`。
- 后端 `backend/pyproject.toml`：仅工具配置段（未声明 `[project]`，避免干扰真实依赖管理）；ruff(含 UP 强制 PEP 604 / ASYNC) + mypy(偏严格，`ignore_missing_imports=true`) + pytest(asyncio_mode=auto) + coverage(`fail_under=70`)。
- `.github/workflows/ci.yml`：backend / frontend / commitlint 三 job，含「目录不存在则跳过」的 guard 步骤，所以现在就能提交。
- 仓库根 `.editorconfig`、`.gitignore`。

### 注意点
- 工作区当前只有文档 + skills，`backend/`、`frontend/` 目录本身还未生成代码，上述配置是**先行基线**，代码生成后即生效。
- husky 钩子需可执行位，Windows 上需 `git update-index --chmod=+x .husky/pre-commit .husky/commit-msg`（或后续在 macOS/Linux 上补）。
