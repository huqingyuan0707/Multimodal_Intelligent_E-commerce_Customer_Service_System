# 数据闭环 + 删除全部 Mock 数据 实施方案（保留 SQLite）

目标（已与你确认）：**保留 SQLite**，补全种子数据让每个页面都有真数据闭环（种子 → 后端 API → 前端渲染），**彻底删除前端全部 mock 数据与演示兜底**。

## 现状（已探明）

- 后端 `seed.py` 已种：1 用户、1 租户、2 SPU+SKU+2 仓库+库存+3 订单+1 待审改价、KB 29 篇、Prompt v1。
- 前端 `src/mock/`（5 文件）被 **19 个消费者**（视图/组件/composable/store）以 `try{真实API}catch{mock}` 兜底引用；`BizScreenView` 还从 mock 导类型。
- **后端缺 `/screen/summary` 端点**（前端在调，后端不存在 → 大屏永远走 mock）。
- 未种数据导致空页：聊天历史（sessions/messages）、工作台队列、看板聚合（cost/slow_traces）、admin 审计、studio 评测、售后单。
- 三个「待实现页」（采购/风控/财务）自带**内联演示行**（非 `@/mock`），无对应后端端点。
- `dev.db` 字段过期（缺 `messages.cost_cents`），需重建。
- 测试：21 个 vitest 文件提到 mock，但**只有 `session.test.ts` 直接从 `@/mock` 导入**；另有 5 个测试断言「失败回退演示数据」行为，需改写为新行为。

## 一、后端（数据闭环）

1. **新增 `backend/app/services/screen_service.py` + `backend/app/api/v1/endpoints/screen.py`**（挂载到 `api/v1/__init__.py`，`GET /screen/summary`）：
   - 4 指标：GMV（`sales_orders.total` 今日/昨日）、自动解决率（`sessions.handoff_status=='none'` 占比）、退货率+Top 原因（`aftersales`）、缺货/预警 SKU 数（`inventory` 可用量 vs `warn_line`）。
   - 近 7 日 GMV 趋势（按日分桶）。
   - 预警列表（库存低于安全线 / 退货突增，`level: bad|info`）。返回 shape 与前端 `mock/screen.ts` 完全一致（`metrics/trend/warnings`）。
2. **扩展 `backend/app/db/seed.py`，新增幂等 `ensure_closed_loop_demo()`**（租户已有 sessions 即跳过），一次灌齐：
   - **sessions + messages**：6~8 个会话覆盖 `handoff_status`（none/pending/handling/resolved）、`handoff_skill`（general/refund/aftersale/complaint）、买家名（王女士/李先生…）、摘要；每会话 2~5 条 user/agent 消息（真实售后/尺码话术、agent 带 citations JSON + trace_id + cost_cents），`created_at` 分布在今日+近 7 日（喂看板趋势），并放 1~2 条「近 5 分钟」消息让 QPS 非 0。
   - **tool_calls**（latency_ms>0，喂慢 Trace）、**cost_records**（usage/estimate 混搭）、**audit_logs**（tenant.create/user.create/quota 等）、**aftersales**（pending/approving/done + 处置类型，挂已有订单）、**eval_runs**（1 条 done 且 `accept_ok:true`，解除 Studio 全量发布门禁）、**promos/coupon_grants/members/reviews/tickets**（喂营销/评价/工单页）、**2~3 个 cs 坐席账号**（喂工作台绩效/转接）。
   - 新增几条**回溯日期**的订单保证 7 日 GMV 趋势有数据。
3. **重建 `backend/dev.db`**（gitignore 已排除）：删除后启动时 `init_models` 重建 + 种子灌入（对齐 alembic head 缺列问题）。
4. **文档同改（AGENTS.md 联动红线）**：
   - `API接口与SSE事件协议规范.md`：补 `/screen/summary`，自查 `openapi.json`。
   - `执行步骤.md`：盘点表状态 + 头部日期版本更新。
   - `数据模型与存储设计.md`：注明 SQLite 为本地默认、MySQL/PG 仅换 `DATABASE_URL` 的既有口径不变。
5. 验证：`py_compile`/`ruff`/`mypy`/`pytest` + 起服务 curl 各端点确有真数据。
