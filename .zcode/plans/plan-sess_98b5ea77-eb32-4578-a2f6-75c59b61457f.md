# 商品管理功能完整实现计划

对齐文档：FRDv2 §FR-10.1 + 页面设计 §3.10 + API接口规范 §4.7 + design.pen goodsRoot

## 一、现状与缺口

### 已实现（最小闭环）
- 后端：`GET /goods`（SPU 分页+SKU 矩阵）、改价恒进审批、SKU 条码/上下架、SPU 上下架
- 前端：GoodsView（SPU 表+SKU 展开行+prompt 改价+改条码+上下架 confirm+分页）
- 审批通过后 `apply_price_change` 自动生效；种子含 2 SPU/6 SKU/3 订单/双仓库存

### 需补齐（对照 FR-10.1 / 页面设计 §3.10 / API §4.7 / 画板）

1. **SKU 库存列缺失**：API §4.7 承诺 `GET /goods` 返回「聚合库存可用量」，后端 `list_goods` 未聚合 inventory，前端 SKU 展开行无库存列
2. **SPU 销量列缺失**：画板 gd_h5 + 页面设计 GoodsTable（SPU/状态/销量），前后端均无
3. **改价未表单化**：画板 gd_pf 要求 PriceForm（当前售价→新售价+原因必填），前端现用 `ElMessageBox.prompt` 且 reason 硬编码"工作台改价"
4. **知识同步缺失**：FR-10.1「商品变更自动同步客服知识（面料/尺码/价格段），避免答旧价」+ 画板 gd_sync 提示条，后端无同步机制、前端无提示
5. **archived 状态缺失**：API §4.7 支持 `on|off|draft|archived`，后端 `GOODS_STATUSES` 无 archived，前端类型/标签/筛选项均无
6. **KnowledgeView 不支持 `?keyword=`**：知识同步提示「查看知识条目」需跳转直达

**明确不做**（对齐现有契约，避免超范围）：新建/编辑商品（API/页面设计/画板均未定义，商品由采购入库产生）、券后价字段（SKU 模型/DDL/画板无此字段，属营销域）、颜色×尺码矩阵格子视图（gd_mx 为增强展示，保持展开行实现）。

## 二、后端改动（backend/）

### Step 1 `goods_service.py`：`list_goods` 聚合库存与销量
- 新增 `_sum_available_by_sku(db, tenant, sku_ids)`：`SELECT sku_id, SUM(qty-reserved-locked) FROM inventory GROUP BY sku_id`，一次批量返回 `{sku_id: available}`
- 新增 `_sum_sales_by_spu(db, tenant, product_ids)`：查 `sales_orders`（status IN paid/shipped/completed），Python 层解析 items JSON 按 sku_id 聚合 qty，回写 SPU 级销量
- `sku_to_dict` 增 `available` 字段；`to_dict` 增 `sales` 字段

### Step 2 `goods_service.py`：新增 `sync_product_knowledge(db, tenant, product, skus)`
- 按 `title LIKE '商品 {spu_no} %'` 查 `kb_docs`；存在 → `document_service.update_doc`（重索引），不存在 → `get_or_create_doc` 新建
- 知识内容（中文 Markdown）：SPU/名称/类目/面料成分(attrs.材质)/尺码范围/全 SKU 售价区间/各 SKU 明细/商品状态
- 触发点：`set_goods_status`、`apply_price_change`、`update_sku`（在 commit 后调用，try/except 不阻断商品操作，异常只 warn 日志）
- topic=`商品`、security_level=`internal`、status=`published`，RAG 检索可命中

### Step 3 `goods_service.py`：`GOODS_STATUSES` 加 `"archived"`，标签加「已归档」

### Step 4 endpoints/goods.py：无变更（现有端点已覆盖，不加新 API）
